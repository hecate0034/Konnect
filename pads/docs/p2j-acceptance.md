# P2 第十批：批准文件的受限原生执行与恢复

日期：2026-11-07。版本：0.11.0。按用户要求，对电源页三个器件推进
“预览 → 执行 → 读回 → 关闭重开 → 完整备份恢复 → 新实例核验”。

## 关键实现选择

本批实现的是**将已批准 BAM 的受限指令转换为 Designer 原生 COM 调用**，不是声称
获得了供应商通用 BAM 文件导入接口。检查到的 `package.exe -b` 明确指定输出文件，
重新运行打包器不能证明执行的就是已批准内容；Layout 的 ProjectIntegration 回标入口
也不提供本批所需的指定文件合同。因此执行阶段不再运行打包器，不重新产生候选。

执行器直接读取保存的批准文件，校验其完整 SHA-256，解析允许的三条实例记录，再通过
`Component.Refdes` 和 `Attribute.InstanceValue` 写入。接口读写定义分别位于用户提供的
Designer Automation Reference PDF 第 310、177 页；本机类型库和真实读回进一步确认。
手册只作接口资料，运行授权来自本次开发和测试副本验收请求。

这条路线满足本批三个对象的文件一致性要求，但不等同于对任意 BAM 指令或原生打包器
全部副作用的实现。返回值明确包含 `native_bam_importer_used=false` 和
`execution_method=pads_native_bam_subset_v1`。

## 接口和执行合同

新增三个 MCP 工具，领域工具合计 31 个，另有两个目录工具：

| 工具 | 输入 | 行为 |
| --- | --- | --- |
| `preview_pads_bam_execution` | 会话 ID、影响报告 ID、完整备份 ID | 复制并锁定候选内容指纹，建立当前/期望状态，生成十分钟有效的执行令牌 |
| `execute_pads_bam` | 执行预览 ID | 复查批准内容和前像，调用原生写入接口，独立读回；令牌只执行一次 |
| `reopen_pads_bam` | 新绑定会话 ID、已执行预览 ID | 原生关闭重开，核对期望结果；再次使会话失效 |

原来的 `impact_id` 仍不能直接执行；必须经过显式转换。MCP 不接受任意 BAM 路径、
命令、脚本、属性名或 COM 成员。历史影响表和新执行表分离。

首批合同刻意限定为 `CORPORATE(Powersupply)` 的三个已验证实例：

| UID | 原位号 | 本次实际位号 |
| --- | --- | --- |
| `$11I15` | C4 | C44 |
| `$11I16` | C2 | C45 |
| `$11I17` | U12 | U32 |

要求三个记录全部存在，实例路径、UID、原位号都一致；目标位号唯一、尚未被使用，
保留原字母前缀。拒绝脚号修改、多单元共享封装、位号交换/循环、范围外实例、器件
身份改变、缺失属性和任意额外属性。目标页外实例仍必须已有效固定为 `Fix`。

`Part Name`、`Part Label` 只接受与原基础值一致、不可见且原来没有实例覆盖的赋值。
本次因此真实创建了 **6 个实例覆盖**，有效属性值没有变化；不是把这些赋值忽略。
三个 `PARAM 23 DELETE` 仅在目标基础属性和实例覆盖中均不存在固定标志时接受，作为
经验证的无操作处理。**真正删除已有固定标志尚不支持。**

预览/执行检查包括：批准文件的原始字节和解析记录、测试工程/策略、完整备份内容摘要、
源 PDB、打包器/导出器/Designer 二进制、应用身份、全部 195 个带位号实例的已记录属性、
目标整页记录以及完整干净的 SCT/Allegro 图。执行前再次读取批准文件；写入阶段只消费
内存中对应这些字节的记录，不加载后来生成的新候选。

预期结果包含每个实例的基础值/覆盖存在性/有效值，以及整页属性、位置、引脚、导线
几何和网络身份；全图投影仅替换三个器件的位号。写后和重开后必须精确等于该预期，
受保护库/PCB/PDB/配置文件必须不变。

## 真实验收与问题处理

新测试目录为 `.pads-runtime/p2j/fixture`，来自相同的官方完整示例，不复用上批修改目录。
在首次打开前建立完整备份：**1,614 个文件、248,685,286 字节**，包括来源清单。
打开后记录原始实时属性、整页和网络图，再只在副本中将页外 192 个带位号实例固定。

本次批准的原始 BAM SHA-256：

`54c752f4694b35690e44511d3e9200902ab8b20bafcdcf30bf3352a51e101a9a`

先对一份私有批准副本追加注释作负面测试：即使解析语义可以相同，完整字节已变化，
`execute_pads_bam` 仍返回 `approved_bam_changed`，令牌标为失效。再次使用该令牌，
以及把原 `impact_id` 当执行令牌，都被拒绝；没有原生写入。随后从未被修改的原始
候选建立新预览，其批准指纹和当前/期望状态与第一份完全相同。

真实执行后已核对三个新位号、六个实例覆盖、未改变的物理脚号和网络连接。再次执行
同一令牌被拒绝；原绑定失效。新绑定后关闭重开，完整读回与期望仍一致。

第一次流程在退出后的稳定性扫描遇到 `database/icdb.dat` 的 `PermissionError`，
停在任何恢复预览和目录切换之前。再次只读扫描时文件已可读，符合原生后台数据库
进程延迟释放文件锁的现象。验收侧 20 秒有界稳定性等待现在同时处理消失文件和读取
占用，要求连续两份完整目录清单相同；持续错误仍停止，不遗漏文件、不重试写入。
这项扩展也补充了自动测试。

保留首次失败收据，从“回标已执行且重开验证成功、编辑器已关闭、尚未恢复”的明确
阶段继续。续验收重新检查已保存结果、工程和批准指纹，仅启动恢复阶段，没有重放回标。

## 恢复与运行边界

恢复使用原始关闭备份，而不是通过反向设置几个属性假装完整撤销。恢复前修改目录
整体保留，切换后逐文件及空目录校验。恢复后另启动 Designer 实例，再比较原始实时
属性、目标整页和全图。这个备份时间点早于页外临时固定，所以正确恢复应同时移除
临时固定设置与本次回标产生的六个覆盖。

原生修改立即持久化，不是原子事务。任何部分/未知写入结果都会消耗令牌、保留记录并
使会话失效；不自动重试、自动反向执行或自动覆盖工程。恢复只能在编辑器关闭后显式
预览执行，且会使旧回标执行记录失效。用户或其他工具不能同时修改验收副本；前后
比较不是原生数据库的全局并发事务。

## 本地证据

供应商工程、库、导出文本和数据库只保留在忽略目录，不提交到远程：

- `.pads-runtime/p2j/original-checkpoint.json` 及 `checkpoints/49df744cb77c49d7a9018205a3a5c031/`：初始完整备份。
- `.pads-runtime/p2j/original-live.json`、`original-sheet.json`、`original-graph.json`：任何临时固定前的原始语义。
- `.pads-runtime/p2j/evidence/impact.json`、`plan.json`：候选及首份执行预览。
- `.pads-runtime/p2j/evidence/bam-execution-ac98987a92604cbaac0204ca3ef050db/`：故意追加注释的私有副本及失效令牌证据。
- `.pads-runtime/p2j/evidence/bam-execution-479de3a332e54f91ac11d45974b2ab25/`：实际批准文件、执行和重开证据。
- `.pads-runtime/p2j/evidence/p2j-0d98c15f/`：指纹拒绝、预览、执行、重开和恢复前停止记录。
- `.pads-runtime/p2j/evidence/p2j-96dce234/`：恢复续验收。
- `.pads-runtime/p2j/evidence/p2j-acceptance-designer.json`：最终机器收据。
- `.pads-runtime/p2j/evidence/p2j-final-checks.json`：最终版本、能力、工具数量、受保护文件与旧令牌状态核验。

`pads/smoke_bam.py` 是开发验收入口；固定准备仍为开发者在已备份副本中的操作。
`--resume-before-restore` 仅接受停在上述明确阶段的收据，拒绝已经进入恢复阶段的记录。
它不由 MCP 接受任意脚本，也不重放已消费的回标令牌。

## 下一阶段建议

下一批建议先把已验证执行合同参数化到少量、明确选择的单单元器件，配套预览式的
范围固定准备和恢复，避免依赖三个硬编码 UID。继续保留“无脚号变化、无交换循环、
无封装拆分、属性有效值不变”等边界，验证新的选择和拒绝路径后再扩大范围。

实际固定标志删除、多单元/共用或隐式脚重映射、位号交换循环仍需独立语义和恢复验证；
不能因本次成功而直接开放。随后继续补齐带标签导线拆分恢复与旋转。完整 P2 尚未完成，
PCB 写入、正式库写入和自动布局布线仍未纳入已验证能力。
