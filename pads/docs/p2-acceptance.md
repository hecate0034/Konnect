# P2 首批验收：已有原理图器件属性与位置编辑

日期：2026-11-06。用户授权范围：测试副本内已有器件编辑，预览、执行、读回和保存重开验证，完成后提交推送。
本报告对应 P2 的第一批功能，不表示新放置器件、创建连接或整个 P2 阶段已经完成。
后续限定范围的几何检查、显式恢复、复用放置与连线结果见 [P2 第二批验收](p2b-acceptance.md)。

## 实现与边界

- 复用 Konnect 协议与工具分组，在独立 PADS MCP 中增加四个工具，总计 14 个领域工具。
- `inspect_pads_component`：读取指定器件坐标、朝向、符号、基础/实例/生效属性及引脚网络身份。
- `preview_pads_component_edit`：形成具体修改前后状态，保存在本地；不写工程。
- `execute_pads_component_edit`：仅执行对应的一次性预览，执行前检查当前状态，执行后读回。
- `reopen_pads_edit`：原生关闭并重开测试工程，再比较已执行结果；旧会话失效。
- 只允许开发者本地配置的独立测试副本，检查工程路径、原生数据库和库位置、来源清单及链接文件。
- 仅 Designer COM 66。属性白名单为 Description、Value、Tolerance、Power、Cost；只修改已有属性的实例值。
  本次真实写入验收覆盖 Description，其他属性仍需分别验证。位号、Part/Cell、符号库和连接写入未开放。
- 坐标单位明确为 0.01 inch（0.254 mm），整数范围 0..10000；无自动避让、吸附、图框边界或 ERC 保证。

## 保存语义的确认

参考三份用户手册中的 Designer 手册，以及本机 66.0 类型库；没有把文档中的示例当作执行授权。

| 接口/事实 | 参考位置（PDF 物理页） | 本次处理 |
| --- | --- | --- |
| Component.GetLocation / SetLocation | Designer 301 / 303 | 读取/写入 1/100 inch 坐标 |
| Attribute.InstanceValue | Designer 177 | 改工程实例值，保留基础值 |
| Component.GetConnections | Designer 299 | 比较目标器件引脚与网络身份 |
| SchematicSheetDocument.Save | Designer 483 | 仅适用于嵌入式符号编辑，不用于本次工程 |
| 原理图直接写入数据库 | Designer 762 | 不把“未保存”当作回滚保障 |
| Application.CloseProject | Designer 70 | 正常关闭后重新打开工程读回 |

因此用户要求的“保存重开”在此实现为数据库持久化后关闭/重开验收。没有伪造一个通用 Save 接口。
这验证的是工程关闭/重开，不是断电恢复、数据库崩溃恢复或完全退出应用进程后的保证。

## 本机真实工程结果

运行环境：PADSProVX.2.4，COM 66，Python 3.13 + pywin32 312。
测试副本为 `.pads-runtime/p2-fixture`，来自已安装 `PADS_Professional_Eval` 的 LessonFinal 和 Library。
未打开或写入正式 GLK 库。

目标是 CORPORATE / control_buffers 上的 R24，UID 和路径均为 `$5I134`。
第一轮坐标从 `(570,500)` 改为 `(580,500)`，Description 实例值改为测试文字。
完整流程通过 18 个实际 MCP 请求，耗时 116.02 秒：

1. 绑定、读取目标；拒绝通过属性工具改位号。
2. 创建两个相同起点的预览；再次读取确认预览没有修改器件。
3. 执行一个预览，读回匹配修改后状态。
4. 拒绝再次执行同一预览；另一预览因实际状态已变化而被拒绝，且没有尝试写入。
5. 独立读取确认说明、坐标及其余已列出属性符合预期。
6. 关闭工程、重开已有图页，检查属性与坐标保留。
7. 旧会话被拒绝，新绑定重新读回一致，随后释放绑定。

最终代码在同一测试副本再次完成 18 个实际 MCP 请求，耗时 120.24 秒：
R24 从 `(580,500)` 移到 `(590,500)`，Description 实例值为 `P2 test copy - R24 x=590`。
预览、执行、独立读回、状态过期拒绝、关闭重开及重新绑定检查再次通过。
每轮移动 10 个原生单位，即 2.54 mm；副本保留第二轮结果供后续复核。

R24 的两条连接在修改后及重开后保持：`$1P2 → $5N138`，`$1P1 → $5N153 / CLK_3584MEG`。
方向和符号名未改变。Description 基础值保留，只改变实例值。

额外交叉核对：11 张原理图、566 个器件类对象、903 个网络对象的 P1 盘点完全一致；
这不是 566 个物理器件，也不等同完整电气网络表。
原始来源 1,613 个文件哈希未改变；测试副本中的 1,261 个库文件及 CORPORATE.pcb 未改变。
收尾再次检查原始来源和副本库文件哈希；已正常关闭本次拥有的测试实例，确认没有残留的 Designer/Layout 编辑器进程。

## 错误处理与测试

预览十分钟有效；原生首次写入前再次检查期限。一次性状态在调用原生写入前落盘，工作进程失败后不会重放。
编辑工具的外层工作进程期限为 150 秒，覆盖会话核验和原生操作各 60 秒的内部期限；
P1 工具仍为 90 秒，避免在正常内部超时清理之前终止编辑监督进程。
同一运行目录中的编辑和显式释放会话共用进程间锁。不会阻止用户在界面中手工操作，
也不协调使用另一运行目录的服务，所以调用期间应避免手工修改或切换工程。

错误不会统一伪装成“没有写入”：原生错误保留尝试写入标记，超时等不确定情况报告未知。
部分失败、读回不一致和超时会使会话失效；不得自动重试。未实现原生原子事务或自动回滚。
工程副本和本地编辑记录保留，供检查或重新从原始样例建立副本。

自动测试覆盖参数、单位、范围、属性白名单、缺少属性、实例值与基础值区分、
预览过期/重复/失效、路径范围、硬链接、并发、会话释放、政策变化、超时、部分写入、
原生只读状态、外部数据库及连接改变后的拒绝。Rust 检查错误标记透传及 MCP 参数契约。
检查结果：58 项 Python 测试、10 项 Rust 测试通过；Rust 格式和 Clippy（警告视为错误）检查通过；
原有参考/环境 MCP 的 11 请求烟测通过，Git 差异空白检查通过。
本地实际证据保留在 `.pads-runtime/evidence/`，不提交专有样例或完整接口转储。
