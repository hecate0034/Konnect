# P2 第六批：有限范围的器件打包闭环

日期：2026-11-07；版本：0.7.0；分支：`codex/pads-native`。

## 本批交付与边界

新增 `preview_pads_packaging`、`execute_pads_packaging`，领域工具总数 23。
继续限定已配置测试副本。首批支持一个已经通过工具复用放置、尚未连接、位号与实时
物理脚号明确的根页器件。必须提供放置前成功的逻辑基线和放置记录；不接受任意工程、
原生命令、库路径、重编号模式或新增库对象。

预览用固定 `package.exe -Add -NoFill -y`（BAM-only）模式及独立工作 PDB，
以工程目录为工作目录。仅接受零字节 BAM：原生程序不能提出位号或物理脚号回标改动。
候选图必须恰好等于原基线加这一个未连接器件，所有原有网络成员不变。

未打包时的 SCT 只用于候选比较，明确标为未验证，容许的诊断仅为准确的
`Error: Design is not packaged!`。预演前后重新导出候选并比较。Allegro 的未打包备用
逻辑会产生不同的电源网络成员，不能作为有效逻辑表；本批不采信这种备用输出。
公共逻辑读取工具继续拒绝未打包状态。执行完成后，SCT 与 Allegro 必须均无诊断、
互相一致、与预览图一致，才算成功。

执行为 600 秒有效期内的一次性操作，执行前再次进行原生预演；核对来源文件、
完整层次器件身份及候选图。执行后核对双格式图、本次新器件实时脚号、操作页状态及
受保护文件。全设计实时核对的是器件身份；全设计脚号与网络成员核对来自原生导出，
并非独立逐脚读取所有实例。`full_design_live_pin_mapping_verified` 仍为 false。

保护范围包括副本的 Library 树、PCB 树、原有 PDB 和项目/检查配置；额外 PDB 搜索
路径拒绝。预演会生成辅助报告、更新工作 PDB 和数据库服务辅助文件，不能描述为
文件完全不变或纯只读。工作 PDB 放在本机证据目录，不写正式库或原有工程 PDB。
未知写入结果会使会话失效并保留证据，不盲目重试。

## 原生探查与真实验收

测试对象：官方示例的独立副本
`.pads-runtime/p2f/fixture/LessonFinal/LessonFinal.prj`。

流程为：取得成功的原始逻辑基线 → 从 C2 复用放置 C900 → 确认公共逻辑读取拒绝
未打包状态 → 打包预览 → 执行 → 拒绝重复执行 → 双格式网络表及 C900.1/C900.2
实时读回 → 关闭重开 → 再读回 → 按放置记录预览并恢复 → 再次重开 → 与原始基线比较。
恢复后的旧放置记录也须拒绝再次打包。

原始 119 个封装器件、320 个逻辑网络，打包后增加为 120 个器件，网络成员不变。
预览核对 196 个带位号的实时实例身份及 1,515 个受保护文件，BAM 为零字节。
优化后的预览实测 70.56 秒；继续使用原有 180 秒原生工作进程、270 秒上层时限，
每个原生打包进程最多 40 秒，未通过延长时限掩盖全量 COM 读取开销。

**整轮验收通过：25 个实际 MCP 请求，536.36 秒。** 成功记录目录为
`.pads-runtime/p2f/evidence/p2f-0ee1a2d6`；汇总为
`.pads-runtime/p2f/evidence/p2f-acceptance-designer.json`。
预览为 70.56 秒，执行及读回为 88.10 秒。打包后新增器件两个物理脚号均明确读回为
未连接；第一次重开后的完整导出图及选定脚记录一致。恢复并第二次重开后，原始
119 个器件、320 个网络、1,233 个已连接导出引脚的图及已记录操作页全部还原。

收尾核对本次实例 GUID、PID、启动时间、工程路径及网格读值 254000，通知所属宿主
正常退出。编辑器退出后再次校验：原始示例 1,613 个文件未变；副本中既有的库/PCB/
Verify.ini 共 1,263 个文件未变；本批新增的更完整保护集合共 1,515 个文件与预览指纹
一致。记录见 `.pads-runtime/p2f/evidence/p2f-cleanup.json`。正式工程和 GLK 库未写入。

回归：**176 项 Python、14 项 Rust 测试通过**；Rust 构建、格式和 Clippy 严格检查通过，
六个本批 Python 文件的 Black 检查通过，原有参考/只读 MCP 冒烟检查通过 11 个响应。
能力查询显示有限范围打包验收为 true，通用写入验收仍为 false。
新增测试涵盖明确脚号/根设计约束、非空 BAM、零退出码下诊断、私有工作 PDB、
预览过期/重复执行、逻辑候选与公共读取隔离、预演前后图/程序/数据库变化、写入后
差异、失败记录和未知结果会话失效。完整故障注入及其他工程仍未验收。

## 发现的问题

- 对完整设计逐个读取全部实时引脚成本过高。改为全设计实时器件身份 + 原生全图
  引脚成员检查 + 新增器件实时逐脚核对，并明确没有全设计独立脚号映射结论。
- 第一轮正式验收在预览阶段因 Allegro 的 `Trying NETLIST logic...` 诊断被拒绝，
  尚未执行打包数据库更新；新增器件已按记录恢复。失败证据保留在
  `.pads-runtime/p2f/evidence/p2f-02084a6d`，恢复证据在 `failed-preview-restoration.json`。
- 原生命令必须在工程目录运行。以证据目录为工作目录时，可能在前面的检查显示成功后，
  才因相对的 `Integration/LocalPartsDB.pdb` 路径失败；不能只解析中间的成功文字。
- `-y` 仍写辅助文件；工作 PDB 也会变化。保护原文件、隔离工作 PDB 并保留报告，
  比笼统声称“预演没有任何文件写入”更符合实测行为。
- 本批恢复是删除本次记录的未连接器件，使操作页和逻辑图回到基线；打包内部记录及
  辅助报告不保证逐字节回滚。已有后续改动时，恢复会拒绝覆盖，需按顺序处理。
- 不支持非空 BAM、隐式物理脚号分配、共用/隐藏脚的完整映射、全部页面几何验证或
  完整 ERC，也未做 PCB 同步、正式库写入及其他 PADS 版本验收。原生操作不是原子事务，
  仍不能阻止用户在另一个界面同时编辑。

## 下一阶段建议

推进 P2，完成电气一致性验证后再进入 P3 原理图/PCB 同步与布局布线。
