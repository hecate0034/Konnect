# P2 第三批：多段路径、接入已有网络与原生检查

日期：2026-11-06。版本 0.4.0；本机 PADSProVX.2.4 / COM 66。
本批仍限定于隔离测试副本，不表示整个 P2 或生产工程编辑能力已经完成。

## 已实现的接口和检查

- 原有修改预览增加 `route`：明确指定两个端点及全部拐点，支持 1–8 段正交导线。
  起点必须为空闲引脚；终点可以是另一空闲引脚，或已有网络的拐点/焊点。
- 现有网络按 UID 和名称同时定位。逐段构造时核对网络 UID，完成后核对整页记录状态；
  既有网络不能被替换、重命名或与另一个既有网络合并。
- 预览拒绝斜线、零长度、冗余共线拐点、回折、自交、无关引脚/网络及器件本体碰撞。
- 撤销已有网络上的分支时只选择新增线段，删除前核验选中集合，删除后验证原拐点和
  引脚连接恢复。部分构造结果仅在符合已知、精确的路径前缀时允许恢复；未知结果不重放。
- 新增 `check_pads_schematic`，总计 20 个领域工具。读取单页物理网络连接表，并独立
  比较器件→网络与原生网络→引脚两种查询结果；保存检查基线并支持后续对比。
- 原生检查调用已安装 `wv/win32/bin/vdrc.exe`，固定启用 `UnconnectedPins`、`ZeroPin`、
  `NetOverlap` 三项。保存原始输出、检查器/规则指纹、错误/警告/提示数量及检查差异。

检查配置生成在状态目录，不修改安装默认配置或工程 `Verify.ini`。定义文件走 `-def`，
固定空白用户覆盖配置走 `-set`；不接受任意命令、可执行文件或外部规则路径参数。
检查器返回零退出码仍可能表示参数错误，因此只有解析到完整有效报告才记为 `completed`。
`profile_clean` 仅对应三项检查，`full_erc_verified` 始终为 false。

## 本机原生试验与验收流程

使用官方 `Documentation/PADS_Professional_Eval` 的完整新副本：
`.pads-runtime/p2c/fixture/LessonFinal/LessonFinal.prj`，设计 `CORPORATE`，页 `Powersupply`。
恢复后的基线为 11 个器件类对象、7 个物理网络；同名 VDD/GND 物理网络仍分别列出，
没有将其误称为已展开的完整逻辑网络表。

1. 记录基线及原生检查结果。基线原有 **0 个错误、1 个警告**：
   `LP2985_BYPASS` 上的悬空线段。该问题不由本批修改产生，也未擅自消除。
2. 复用 C2 的已有符号/元数据放置 C900、C901、C902。新增 6 个未连接引脚；
   三项原生检查检出 **9 个错误、1 个警告**，作为检查器有效工作的正向故障样例。
3. C900 脚 1 连接 C901 脚 2，路径为
   `(300,300)→(300,400)→(600,400)→(600,500)`。
4. C902 脚 1 接入上述网络的 `(600,400)` 拐点，形成三引脚分支。
   检查网络身份和三端连接，关闭重开核验，并验证有后续分支时拒绝恢复早期主路径。
5. 恢复分支后，C902 脚 1 接入原有 VDD 网络 `$11N3` 的 `(895,1025)` 拐点，
   路径为 `(800,300)→(800,350)→(700,350)→(700,1025)→(895,1025)`。
   核验原网络名称、UID、原引脚以及新增引脚，关闭重开后再运行原生检查。
6. 逆序恢复 VDD 分支、测试主路径及三个新增器件；关闭重开，与初始整页记录、
   双向网络连接表、原生检查数量和完整问题文本对比。
7. 校验全部原始文件以及复制库、PCB、Verify.ini 的哈希。

`p2c-acceptance-designer.json`。不提交专有工程、手册、原生完整转储或生成的规则定义文件。

## 遇到的问题及修正

- `AddNet` 的无器件引脚端点需要 `VT_DISPATCH` 类型的空对象；Python 普通空值会导致
  原生类型不匹配。已使用显式类型，实际连续线段合并为一个网络。
- 分支必须从既有网络端开始构造，逐段保持 UID。恢复通过选中新增线段完成，
  不能删除整个已有网络再重建；原生试验已核验原拐点与网络身份保持。
- 工程默认配置关闭了较多检查。简单运行得到的“0 错误”不能代表连接正确；
  采用明确的三项检查，并以故意未连接器件验证其确实报错。
- 原生检查器区分规则定义和用户覆盖配置；把定义文件当作用户配置会返回读取错误，
  且退出码仍为零。适配器保留安装定义的字节格式、生成独立 profile，并严格解析完成摘要。
- 原始工程已有告警。验收采用修改前后差异及恢复基线，不把原有问题掩盖成全项目通过。
- 沿引脚端部横向离开时，原生编辑器会插入 5 单位短折线。首次 VDD 接入因此被整页
  读回拒绝；保留失败记录，逐项核对实际折线后使用受限的开发恢复流程还原副本。
  现预览要求从唯一明确的包围框边缘垂直向外出线，拒绝沿边切向出线和边角等歧义位置；
  验收路径显式给出出线段，不能把原生临时改变的路径自动解释为用户预览已通过。

- 100 项 Python 测试、12 项 Rust 测试通过；Clippy 严格检查通过。
- 原有只读 MCP 回归通过 11 个响应；参考查询和无效参数拒绝保持正常。
- 单元测试覆盖路径拒绝条件、原网络身份保护、已观测部分路径恢复、原生报告失败识别、
  只启用指定检查、检查基线作用域和失败结果不写入成功记录。
- 原生完整操作流程覆盖多段连接、分支恢复、既有命名网络接入、双向连接表和检查报告对比。
  对部分路径故障的自动恢复分支，目前由单元测试及已观测原生路径前缀验证，未注入所有 COM 故障。
- 暂不支持线段内部拆分接入、已有网络合并、跨页/层次/全局网络展开、总线、隐藏电源脚、
  旋转和多单元封装处理；三项检查不包含完整驱动冲突、电源连接、库封装或 PCB 同步规则。
- 仍按已记录器件、引脚和导线字段比较，不覆盖全部文字/标签外观，也不保证数据库字节还原。
- 操作不是原子事务；同一状态目录中的操作串行，不能阻止用户手动修改或另一部署修改。
  未知超时状态必须检查后处理，不自动恢复或盲目重试。
