# P2 第四批：中部接入、标注保护与分级电气检查

日期：2026-11-06。版本 0.5.0；本机 PADSProVX.2.4 / COM 66。
仅在完整隔离副本验收，P2 整体尚未完成，未开放生产工程、PCB 或正式库写入。

## 本批实现

- `route` 支持从空闲引脚接入一个明确的正交线段中部。原网络 UID/名称不变，
  原线段拆成两段并形成焊点。总线、已有网络合并、歧义交点仍拒绝。
- 原生读取增加线段标签（包括不可见标签）的文字、解析名、范围、位置、方向、字号、
  字体等，以及线段属性值。目标线段有标签或属性时拒绝中部接入；没有原生检查标记
  的旧记录也不能直接授权拆分。其他线段已有标签纳入整页比较。
- 恢复只选中原计划的新增路径线段，不再用“原几何中不存在的边”判定删除对象。
  否则拆出的两段原线也会被误选。实际 SDK 试验确认：删除支路后 PADS 自动合并原线，
  无须删除重建网络或执行通用 Undo。读回必须恢复原几何、连接、身份和记录的标注。
- `check_pads_schematic` 增加 `profile` 与 `scope`；旧调用默认行为保留。
  `connectivity` 仍为三项检查；`electrical` 为下表八项检查。
  `sheet` 用 `-page` 请求所选页面；原生 flat-net 规则仍按检查器的全局连接语义解析。
  `design` 请求根设计全部页面，不加 `-hier`；不独立声称层次展开已验证。
- 整设计检查前后盘点 `(sheet, UID, name)`，最多 5000 个物理网络，列出跨页同名候选。
  不按名字合并网络，候选显式标记 `electrical_equivalence_verified=false`。
  返回的双向引脚连接表仍只覆盖选定页面，不宣称已独立建立全局/层次逻辑网络表。
- 检查基线要求同工程、同页、同规则、同范围及同检查器指纹；混用基线在原生检查前拒绝。
  原始输出和配置指纹保留本地，安装默认配置与工程 Verify.ini 不改动。

| 原生规则 | 作用 |
| --- | --- |
| UnconnectedPins | 未连接引脚 |
| ZeroPin | 悬空网络段 |
| NetOverlap | 网络重叠 |
| Undriven | 未驱动网络 |
| MultDriv | 多输出驱动 |
| DriveGlobal | 输出直接驱动全局网络 |
| OutputDirectlyPG | 输出直接连接电源/地 |
| PowerGroundPinConnection | POWER/GROUND 引脚连接规则 |

继承已安装规则定义的选项并保存指纹；不承诺这些选项适用于所有电路。
`completed` 只表示检查完成，`profile_clean` 只对应所选规则，`full_erc_verified=false`。
本次真实报告出现未驱动、多驱动、输出接电源/地和驱动全局网络的问题；未逐项人工注入
八种故障，也没有做电源完整性或器件额定值仿真。

## 实际验收

使用官方示例的新副本 `.pads-runtime/p2d/fixture/LessonFinal/LessonFinal.prj`，
设计 CORPORATE，操作页 Powersupply。先完成私有 SDK 分段/恢复试验并还原基线，
再通过实际 Rust MCP 服务运行 `pads/smoke_routes.py --interior`。

1. 记录单页和整设计电气基线，确认不同范围基线不能混用。
2. 复用原 C2 放置 C900、C901、C902；连接前的六个空闲引脚作为检查正向样例。
3. 主路径 `(300,300)→(300,400)→(600,400)→(600,500)`；C902 的支路
   `(800,300)→(800,350)→(450,350)→(450,400)` 接入水平线中部。
   精确验证三段变七段、三端引脚、原 UID、重开后状态，再恢复支路并再次重开。
4. 拒绝接入 VDD `$11N3` 带不可见标签的线段中部 `(895,1040)`。
5. C902 经 `(800,300)→(800,900)→(850,900)→(850,945)` 接入原命名网络
   LP2985_BYPASS `$11N4` 的无标注线段；该网络其他线段的原标签须保持。
   读回、重开和原生检查后逆序恢复全部更改。
6. 与基线比较整页记录、单页引脚连接表、整设计物理网络盘点和原生问题文本；
   检查原始文件、复制库、PCB、Verify.ini 的 SHA-256。

实际验收通过：**50 个 MCP 请求，787.35 秒**，运行目录
`.pads-runtime/p2d/evidence/p2d-091ebef4`；汇总文件
`.pads-runtime/p2d/evidence/p2d-acceptance-designer.json`。

最终恢复为 11 个器件类对象、7 个物理网络；整页记录及双向引脚连接表与基线一致。
根设计盘点 753 个物理网络，列出 187 组跨页同名候选；恢复后的盘点、原生完整问题文本
及计数均与基线一致。候选数量不等于已验证的跨页逻辑网络数量。

## 兼容性问题与边界

- 不可见网络标签确实存在于官方示例，不能靠屏幕上有没有文字判断可拆分。
- 读取全设计每条线段的标签成本较高，初次探查约 109 秒。因此正式整设计盘点只记录
  网络身份/名称，完整标签检查限定操作页；保留 180 秒原生工作进程及 270 秒上层期限，
  未通过扩大等待期限掩盖性能问题。整设计盘点不证明其他所有页面的几何没有变化。
- 更严格规则揭示示例原有电气问题：操作页有 LP2985_BYPASS 未驱动、GND/VDD
  多驱动、U12 VOUT 接电源/地、V2.7 被输出驱动，以及原有悬空段告警。规则输出需结合
  实际电路人工评估；验收采用差异和恢复一致性，不擅自修改示例电路。
- 新版记录包含标注字段，旧版预览/恢复记录会因状态不匹配而拒绝。升级前用对应旧版
  完成已有修改的恢复，升级后重新预览；不静默补齐或忽略缺失字段。
- 仍不是原子事务，不能阻止用户同时手动编辑。部分路径恢复有纯逻辑测试，未知超时
  不盲目重试；本批未完成全部 COM 故障注入。
- 带标签/属性线段拆分、全局/跨页/层次引脚等价、多单元、隐藏电源脚、旋转、PCB
  同步与完整 ERC 尚未验收。当前 20 个领域工具的数量不变。
