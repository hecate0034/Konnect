## 真实读取结果

| 数据 | 结果 | 计数含义 |
| --- | --- | --- |
| 原理图页 | 11 | 原生 QueryPages 返回的图纸 |
| 原理图器件类对象 | 566 | 含无位号的图形/层次等对象，不是 566 个物理器件 |
| 不同非空原理图位号 | 119 | 在 PCB 中全部找到对应位号 |
| 原理图网络对象 | 903 | 原生 DesignNets 对象，不等于物理网络去重数 |
| PCB 器件 | 121 | 多出 TV1、TV2，它们不在所查历史网络表的引脚引用中 |
| PCB 网络 | 320 | Document.Nets 默认集合；不宣称包括所有未连接引脚网络 |

历史 `PCB/Logic/Netlist.aug` 包含 119 个不同器件位号，全部在本次 PCB 盘点中找到；
320 个 PCB 网络名也均在该历史网络表中。历史表有 360 个网络名，计数不直接等同于
当前默认 API 集合。此交叉核对不证明当前原理图与 PCB 已同步，也不替代引脚连接检查。

两端各运行 11 个真实 MCP 请求，涵盖错误目标、绑定、实时核验、完整对象盘点、快照比较、
释放、已释放会话拒绝及重新绑定。最终一轮原理图流程约 104 秒，PCB 约 18 秒；
这是包含两次全量读取及多次绑定核验的总耗时，不是单次请求耗时。原生单次读取上限为 60 秒，
较大或忙碌工程可能触发超时，明确报错后需要重新绑定。

## 会话与故障验收

- 工程路径、安装目录、实例 GUID、PID、进程启动时间均进入绑定条件。
- 在同一 Designer 进程中从 `LessonFinal.prj` 切换到 `BindingTarget.prj` 后，旧会话实际返回 `target_mismatch`。
- 应用退出后的旧会话返回 `application_not_running` 并失效；重启后的新实例必须重新绑定。
- 副本重开、切换后，原生 UID 与已列出属性集合和原始读取一致；排序不影响快照摘要。
- 实际遇到的弹窗阻塞返回 `application_busy_or_modal`，不自动点击、同步或修改设置。
- 开发期实际超时返回 `native_timeout` 并使会话失效。客户端不会得到伪成功空列表。
- 释放会话仅更新本地账本；再次绑定时原编辑器的实例身份保持一致，证明释放未关闭编辑器。
- 单元测试覆盖 PID 复用、实例变化、工程文件变化、外部安装、缺少原生 UID、快照过期和并发释放。
- 启动失败及退出后的残留进程只按本次记录的 PID、可执行文件路径和启动时间清理；最终核对没有遗留测试编辑器。MCP 会话工具本身不结束应用进程。

31 项 Python 测试、8 项 Rust 测试通过；原有参考工具的 11 请求回归继续保留。

## 实现与边界

MCP 只允许固定工具。原生适配器从运行对象表附加已有进程，按 PID 和完整身份复核；
不通过工具参数执行任意 COM 成员、脚本或路径中的程序。初次绑定遇到多个实例时拒绝猜测。
Designer 需已有图纸打开，才能利用原生视图窗口确定进程身份。

部分 VX.2.4 COM 属性在普通 PowerShell 访问时会静默为空或读取耗时不稳定。
最终使用 pywin32 的显式原生读取；Designer 的部分零参数方法显式以方法形式调用。
Layout 的许可 DLL 是 32 位，因此仅许可握手保留独立的 32 位辅助进程；挑战值和令牌只在管道
和内存中使用，不进入日志、会话记录或 Git。许可握手是厂商文档规定的流程。

`snapshot_token` **只涵盖返回的对象身份和属性**。它不涵盖坐标、导线几何、完整引脚网络映射、
布线或未列出的数据库状态，也不是事务锁。`validate_pads_snapshot` 不授权任何写入。

P2 写入执行层必须额外实现：对具体修改生成预览；复核所有相关原始字段与原生工程状态；
在适当的原生事务/撤销边界内执行；读回、保存重开核验；失败时报告部分执行状态及恢复办法。
不能把 P1 的通用快照比较直接当作完整写入保护。
