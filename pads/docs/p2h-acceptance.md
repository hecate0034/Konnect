# P2 第八批：非空回标影响预览与恢复条件

日期：2026-11-07。版本：0.9.0。本批按用户要求先实现非空回标影响预览，在测试副本
验收。未应用非空 BAM，未开放非空回标执行或自动逆操作。

## 成果与接口

新增 `preview_pads_backannotation`，领域工具总数 25。输入为绑定会话、已有设计、
固定模式和可选基线。默认 `add` 使用原生 `-Add -NoFill -y`，
`repackage_unfixed` 额外使用 `-r`，可提出全设计未固定器件重新分组及编号的候选。
两种模式都使用私有工作 PDB，始终保留 `-y`，没有应用 BAM 的调用路径。

返回的 `impact_id` 保存在独立的历史影响表中，不是可执行预览令牌；传给已有打包
执行工具会被拒绝。已有空 BAM 打包执行范围保持不变。

预览报告包含：

- 按完整层次作用域和原生 UID 定位的器件位号变化，以及封装单元拆分/合并候选。
- 原生脚 UID、脚名、旧/新物理脚号及对应旧逻辑网络。BAM 注释中的旧值必须与实时
  引脚、SCT 脚名和双格式导出成员核对，不能仅凭注释推断。
- `Part Name`、`Part Label`、`Tolerance` 的原基础值、实例值、有效值和拟设置值。
- 参数 23 固定标志删除指令。其原始标志状态尚未独立读取，明确标记恢复证据缺失。
- 候选网络成员标识变化、无法唯一推导的成员和潜在脚号/网络冲突。成员标识变化
  往往来自位号或脚号改变，不等于已经发生断线、连接或短路。
- 两次原生预演的逐实例差异及恢复阻断项；所有候选与原生报告保存在本机证据目录。

BAM 解析仅允许本机实测的 `CHANGE ... INSTANCE`、`SELECT COMP`、参数 15、
`PIN_PARAM ... 4`、参数 23 删除和上述三个属性设置。未知命令、重复选择/赋值、
缺失旧值、格式不完整或与原生日志变化数量不符时拒绝。没有执行文本或任意 COM/命令入口。

## 恢复条件和执行边界

| 变化类别 | 已记录内容 | 执行前仍需满足的恢复条件 |
| --- | --- | --- |
| 位号 | 原/拟位号、完整实例路径、UID | 证明身份保持；解决编号冲突及循环重命名；验证逆操作而非简单倒序文本 |
| 单元/物理脚 | 原生脚号、脚名、拟脚号，旧网络成员 | 完整 Slot、共用脚和隐藏脚归属证明；封装拆分/合并必须具有明确逆映射 |
| 属性 | 基础/实例/有效值、拟设置值 | 确认实例覆盖是否真实存在；空实例值不证明“无覆盖”，有效值相同也不保证归属相同 |
| 固定标志 | 参数 23 删除候选 | 独立读取原状态并验证精确恢复方法；目前未满足 |
| 网络 | 修改前完整原生图、候选成员投影及未解析项 | 执行后及恢复后均须双格式独立导出；恢复图应等于原始基线，随后关闭重开复核 |
| 工程整体 | 来源、工具、受保护文件与应用身份核对 | 在未来执行前关闭编辑器，取得完整且可独立重开的工程/库备份；本预览不创建该备份 |

`executable_preview`、`write_authorized`、`recovery_verified` 始终为 false。
未知结果或中途变化保留证据并使会话失效，不盲目重复执行，也不把备份文件覆盖到
仍然打开的数据库。本批验收的是影响预览及恢复条件报告，**不是恢复操作验收**。

## 真实测试副本验收

对象为官方示例的新副本：
`.pads-runtime/p2h/fixture/LessonFinal/LessonFinal.prj`，设计 `CORPORATE`。
观察到 195 个带位号的实时实例；原生完整导出包含 119 个封装器件、320 个网络。

流程：绑定 → 空 Add 预演 → 非空重打包预演 → 拒绝把影响 ID 当成执行令牌 →
拒绝未知模式及错范围基线 → 释放 → 原生关闭重开 → 重绑 → 再次预演并比较 → 释放。
每次预览内部均进行两次 BAM-only 原生调用，前后检查实时记录、受影响引脚、完整
SCT/Allegro 图及 SCT 脚名、程序指纹、保护集合和工程/应用身份。

**13 个实际 MCP 请求，272.44 秒，通过。** 空预览约 74.61 秒，首次非空预览约
88.27 秒，重开后的预览约 78.42 秒。结果目录为
`.pads-runtime/p2h/evidence/p2h-d3d2f852`，汇总为
`.pads-runtime/p2h/evidence/p2h-acceptance-designer.json`。

| 本轮结果 | 重开前首个候选 | 重开后首个候选 |
| --- | ---: | ---: |
| 受影响实例 | 133 | 133 |
| 位号变化 | 130 | 130 |
| 物理脚号变化 | 96 | 93 |
| 属性设置 / 有效值变化 | 270 / 0 | 270 / 0 |
| 固定标志删除 | 133 | 133 |
| 可推导的网络成员标识变化 | 1121 | 1112 |
| 未能唯一推导的网络成员 | 44 | 53 |

示例：`CORPORATE(control_buffers)` 的 `$5I136` 提出 R25→R10；
`CORPORATE(microprocessor)` 的 `$3I3251`、引脚 `1Y4` 提出 U14.17→U3.12，
旧网络为 `LED2_TST_ALM`。这些是冻结在本次报告中的原生候选，不是已经执行的结果。

**重复预演不稳定是本批重要发现。** 重开前同一次查询的两份 BAM 均为 43,316 字节，
但有 8 个实例的候选不同；文件大小相同不能当作内容相同。重开后的两次预演也不
一致，重开前后的影响报告同样不同。实时实例/所观察属性及完整导出图保持一致，
因此把“来源变化”与“候选变化”分开报告；不把候选差异隐藏掉，也不声称它们已经
证明电气等价。具体差异保留在 `repeatability.changed_instances`。

收尾核对本次编辑器 GUID、PID、启动时间、工程路径和网格值 254000，再通知所属
宿主正常退出。退出后校验原始示例 1,613 个文件、副本库/PCB/PDB/配置等 1,515 个
受保护文件均未变化；记录见 `.pads-runtime/p2h/evidence/p2h-cleanup.json`。
正式工程及 GLK 库未写入。预演产生辅助报告和私有工作文件，不宣称文件系统纯只读。

回归：**285 项 Python、16 项 Rust 测试通过**；Rust 构建、格式、Clippy 严格检查
通过，六个本批 Python 文件的 Black 检查通过，参考/只读 MCP 冒烟检查通过 11 个响应。
能力查询显示回标影响预览验收为 true，通用写入验收仍为 false。

新增测试覆盖不支持/截断/重复 BAM、旧值冲突、非唯一目标、原生脚名不符、封装拆分/
合并、共用脚不确定、候选脚网络冲突、属性覆盖未知、影响记录与执行令牌隔离、基线
范围/来源、原生命令固定为 BAM-only、诊断/数量不符/超时，以及实时记录、引脚、
导出图/脚名、保护集合、工具、PDB、实例和路径的变化。故障测试为模拟注入，没有
在真实副本中故意破坏数据库，也没有进行非空回标应用。

## 问题、限制与下一阶段建议

- Native `-r` 重打包对多单元分组存在候选差异，不能将“预览后重新运行 packager”
  当作精确执行第一份候选的办法。此前探查中的首次拒绝证据仍保留在
  `.pads-runtime/p2h/evidence/backannotation-535c344b02a34eca908ebf34a0b16f1f`；当时
  未进入任何应用步骤。
- 本批只记录三个属性和首份候选涉及的显式引脚；不是全页面几何、全部属性或全部
  固定标志的独立核验。隐藏脚/共用脚及拆分封装的未知成员明确保留，不猜测目标。
- 要求已经能够干净导出的打包状态。暂不接受额外 PDB 搜索路径、直接总线段映射、
  任意 BAM 导入或其他命令结构。每份 BAM/日志限 1 MiB，最多 512 个目标、256 处
  脚号变化和 1,000 个扫描对象；更大工程及其他 PADS 版本未验收。
- 原生子进程仍限 40 秒，总原生工作进程 180 秒，上层 270 秒。没有扩大时限；
  异常或超过边界会拒绝，不声称有原子事务或能阻止界面并发编辑。

建议下一批先缩小候选作用范围，验证候选固定/重现机制，并补齐固定标志及实例属性
覆盖归属读取；同时建立关闭状态下的完整副本备份、独立重开和恢复验收。满足这些
条件后，再选择单器件、无单元合并且无隐藏脚歧义的最小非空回标执行用例。随后继续
带标注线段拆分/恢复和旋转，再进入 P3 原理图/PCB 同步与布局布线。
